WHAT IT IS
--------------------------------------------------------------
One page that lists every recurring Energy Group process and, for each one:
  name, cadence, one-line purpose, owner, how to run it (run.bat or SOP.txt),
  the phrase to give Claude Code, LAST VERIFIED date, last run date and result,
  and a status: ATTENTION (last run FAILED), DUE (older than the cadence window),
  NOT RUN (no log yet), OK, AD HOC.
Click a row for the process folder paths (local and shared-drive backup) and the
"if it breaks" phrase. Click a status card to filter.

It is the entry point that outlives sessions, laptops and people: a person who has
never done the work opens the page, opens the folder it names, reads README.txt,
and runs it.

WHERE THE FACTS COME FROM
--------------------------------------------------------------
The SOP library: C:\Users\john.slagboom\Desktop\Git\sops\  (one folder per process;
backup R:\0 - Meter+Billing Process Docs\sops\). The builder reads, per folder:
  sops\INDEX.md            folder | cadence | what it does | last verified
  README.txt               LAST VERIFIED (fallback)
  last-run.log             newest dated line -> date + SUCCESS / FAILED / LOGGED
  status.txt, monitor-log.csv, and config.json "script_log"   (the automated monitors)
  run.bat present?         -> "double-click run.bat" or "follow SOP.txt"
The builder never edits the library. The page cannot drift from the folders because
it has no facts of its own.

WHAT NEVER GOES ON THE PAGE
--------------------------------------------------------------
The repo is public on GitHub; the password gate is client-side JavaScript and the
JSON is fetched in the clear. So the builder publishes only: names, cadence text,
a one-line purpose cut at the first file path or parenthesis, owner, dates, and
result words. Never: dollars, gallons, meter reads, bill rows, SOP steps, config
values, server paths. The sops folder itself stays gitignored (rule since 06/11/2026).
Detailed status for the housing water bill lives on the shared drive instead:
R:\0 - Meter+Billing Process Docs\Housing Water Billing\STATUS.html (written by that
process's run.py on every run).

HOW IT STAYS CURRENT (no one has to remember)
--------------------------------------------------------------
  Mondays 07:10   update-data.sh runs the builder before its push step; push-data.sh
                  includes data/processes.json in its file list.
  Every housing water bill run   sops\housing-apartment-water-billing\run.py calls the
                  builder with --push at the end (non-fatal if offline).
  Every Claude recall or capture   the plan-process-check skill runs the builder with
                  --push after it logs the run.
  By hand         update-processes.bat.
Publishing goes through push-data.sh (GitHub Contents API), not git push, because the
local checkout is usually behind GitHub after the Monday API pushes.

STATUS WINDOWS
--------------------------------------------------------------
  weekly 10 days, monthly 40 days, annual 400 days (CADENCE_WINDOW_DAYS in the builder).
  Cadence class comes from the INDEX.md cadence text: weekly / monthly / annual / ad hoc.

TROUBLESHOOTING
--------------------------------------------------------------
  Symptom                                  Cause                              Solution
  Page says could not load processes.json  data/processes.json not on GitHub  run update-processes.bat; check push output
  A process is missing                     folder has no INDEX.md line        add the line (plan-process-check capture); rerun
  NOT RUN but it did run                   the run did not write a dated line add the line to last-run.log (MM/DD/YYYY HH:MM | SUCCESS)
  Description shows a path or a figure     INDEX.md line starts with one      reword the INDEX.md line; the builder cuts at the first path
  Push fails                               network or token                   run update-processes.bat later; token lives only in push-data.sh
